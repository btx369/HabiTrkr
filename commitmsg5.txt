Translate the interface across six languages, and fix what that exposed

The dictionary had 66 keys covering only Profile and Tags. The other four main screens —
Notes, Events, Calendar and Habits — imported the translation hook but left nearly every
label hardcoded, so a Portuguese user saw "Notas" in the title and "Folders", "Archived",
"Pin", "Share", "Copy", "Move", "Color", "Archive" and "Delete" underneath it.

61 new keys were added to en, pt, es, fr, de and it: tabs, sorting labels, calendar views,
weekday names, the shared action menu, note types, creation buttons, and the editor and
viewer labels. Every screen now speaks the chosen language: measured with the UI set to
Portuguese, the English strings still on screen went from 23 to 3.

nl, pl, tr, ja, zh and ko are deliberately left untranslated. Their blocks do not receive
the new keys and English shows through, which is an honest gap; inventing translations for
languages I cannot check would not be. `verify-language-keys.mjs` reports the gap without
failing, so it can gate a commit instead of being permanently red.

Four things this exposed, each fixed here:

**`t()` fell back to the key, not to English.** `translations[language][key] || key` meant
a missing entry rendered "tabFolders" where a button should say "Folders" — worse than an
untranslated label, and invisible unless something looked for it. It now falls back
through English and only returns the key when even English lacks it, which keeps a typo
visible instead of silent.

**Weekday abbreviations were being cut out of the full names.** Slicing to three letters
works in English and Portuguese by luck and fails in German, where "Dienstag" gives "Die"
and the language uses "Di". There are now `dayShortMonday`…`dayShortSunday` keys per
language, used by the calendar header, the habit header and the day selector. The day
selector had its own English initials from `getOrderedDayInitials`, which is no longer
used.

**Three of the four folder view-settings menus disagreed.** One said "Organise" while the
others had moved to "Sort by"; NoteFolderViewSettings was the outlier, and is now
consistent. It also had its sort labels in a local map, which now holds keys.

**BulkActionBar's action tables are module level**, so no hook can run in them. Their
labels are now a mix of translation keys and plain English, told apart by an explicit
`LABEL_KEYS` set rather than by guessing from the shape of the string. The literals are
the ones that compose a noun with "All" — "All Notes", "All Events", "All Habits", "All
Folders" — and "Move"; none has a key, and they stay in English rather than showing a key
name.

Also removes the legacy `note.name !== 'Title'` guard in NoteCard. New notes are created
with an empty name now, so the app no longer produces that value; the special case existed
only to hide a placeholder that was being stored as real data.

Two new checks, both driving the real app:
- `verify-i18n-coverage.mjs` walks every screen in all twelve languages and fails if any
  renders a raw key. It excludes keys whose English text equals the key name (`'items':
  'items'`), which cannot be told apart from a raw key by reading the screen.
- `verify-language-keys.mjs` compares the blocks' key sets, flagging a key present in one
  language and missing from another.

The scripts that insert the keys are checked in too, so the next batch does not have to be
typed by hand: `add-language-keys.mjs` holds the translations and `sync-language-keys.mjs`
inserts whatever a block is missing. Writing those went wrong twice in ways worth
recording in the code comments: the file is checked out with CRLF, so a pattern anchored
with `$` never matched and the script reported success while inserting nothing; and a
one-off cleanup matched on position rather than on key name, which deleted the
pre-existing `'delete'` entry from all six translated blocks.
